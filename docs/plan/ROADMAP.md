## 1. 디자인 시스템 완성 — 타이포·간격·그림자

**상태**: 미착수 · 바로 착수 가능 · 상세 계획서 없음(이 문서가 유일)

### 왜

[테마 시스템](complete/theme_system_plan.md)으로 **색과 모서리(radius)** 는 토큰화됐지만, 디자인의
나머지 축은 여전히 코드에 박혀 있다. 지금의 "테마"는 정확히는 **컬러 테마**다.

```
text-[11px] × 35곳,  text-[13px] × 26곳,  text-[10px] × 24곳,  text-[12px] × 15곳 …  (100곳 이상)
```

**테마를 토스로 바꿔도 글자 크기·폰트·간격은 그대로다.** 원본 가이드는 이 정보를 갖고 있는데
쓰지 않고 있다:

| 가이드 절 | 빌드가 파싱? | 출력에 사용? |
|---|---|---|
| ③ 컬러 시스템 | ✅ | ✅ |
| ⑥ Border Radius | ✅ | ✅ |
| ⑤ 스페이싱 | ✅ | ❌ **버려짐** |
| ⑦ Shadow / Elevation | ✅ | ❌ **버려짐** |
| ⑩ Motion | ✅ | ❌ **버려짐** |
| ④ 타이포그래피 | ❌ 서술형이라 파싱 불가 | ❌ |

### 무엇을

1. **타이포 위계 정의** — `text-[11px]` 같은 절대값 대신 역할 이름을 쓴다.
   `text-caption`/`text-body`/`text-title` … Tailwind v4 의 `@theme` 에 `--text-*` 로 등록.
2. **가이드 ④ 절 구조화** — 현재 서술형("Display: 56px / 800 / 1.05 / -0.025em")이라 자동 파싱이
   안 된다. 파싱 가능한 형태로 바꾸거나, 활성 15종만 `overrides/` 로 손으로 채운다.
3. **⑤⑦⑩ 출력 연결** — 이미 파싱하고 있으므로 `@theme` 매핑만 추가하면 된다.
   그림자는 `shadow-[0_-2px_10px_rgba(0,0,0,0.05)]` 3건도 함께 정리.
4. **100곳 이상 치환** — 색상 치환(276건) 때와 같은 방식. 역할 매핑표를 먼저 정하고 일괄 치환 후
   스크린샷 비교.

### 유의

- **폰트 자체는 별개 문제다.** 가이드는 Pretendard·Toss Product Sans 등을 지정하지만 웹폰트를
  실제로 싣는 건 다른 작업이다(용량·라이선스). 1차에서는 크기·굵기·자간만 다룬다.
- 색상 치환 때 배운 것: **범주형 팔레트와 고정 배경 문맥은 토큰화하면 안 된다**
  ([theme README](../../frontend/src/theme/README.md) 참조). 타이포에도 같은 함정이 있을 수 있다
  (예: 터미널 로그의 `font-mono`).

## 2. 배포 — Railway 이전

**상태**: 검토 중 · 상세: [`pending/railway_migration_plan.md`](pending/railway_migration_plan.md) (537줄)

### 왜

지금 어드민 API(FastAPI)는 **로컬에서만** 돈다. 공개 대시보드는 Vercel 정적 배포라 잘 돌지만
(백엔드 없이 자립), 프로젝트 생성·정제 실행은 로컬 백엔드가 떠 있어야 한다.

### 막는 것

**"어드민을 원격에서 써야 하는가"가 확정되지 않았다.** 지금처럼 로컬에서만 정제하고 결과만
배포하는 방식으로 충분하다면 이 작업은 불필요하다.

### 유의

- 이전하면 **3번(클라우드 스토리지)이 따라온다** — Railway 는 무상태 컨테이너라 로컬 디스크
  `/storage` 가 재시작 때 날아간다.
- `backend/Dockerfile` 은 이미 pip 기반으로 정리돼 있어 컨테이너화 준비는 돼 있다.

## 3. 클라우드 스토리지 연동

**상태**: 검토 중 · **2번에 종속** · 상세: [`pending/cloud_storage_plan.md`](pending/cloud_storage_plan.md) (95줄)

### 왜

무상태 컨테이너에 배포하면 `storage/` 의 프로젝트 레시피(`config.yaml`·`dashboard.json`)와 원본
엑셀이 재시작 시 사라진다. `StorageEngine` 추상화를 두고 Supabase Storage 로 뺀다.

### 막는 것

**2번이 결정되기 전엔 의미가 없다.** 로컬 운영에서는 로컬 디스크로 충분하다.

## 4. 데스크톱 앱 (Tauri)

**상태**: 미착수 · 상세: [`pending/tauri_integration_plan.md`](pending/tauri_integration_plan.md) (169줄)

### 왜

설치 없이 오프라인에서 쓰는 단일 실행 파일. Tauri + Python Sidecar 로 기존 `frontend/`·`backend/`
를 **건드리지 않고 격리된 폴더**에서 패키징하는 A안이 잡혀 있다.

### 막는 것

**오프라인 배포 요구가 확정되지 않았다.** 그리고 **6번과 목적이 겹친다** — 둘 다 "설치 없이 로컬에서
쓰기"다. 착수한다면 **택일**해야 한다.

> 6번(Gradio/PyQt)보다 이쪽이 유리하다: 이미 만든 React UI 를 그대로 쓰고, 기존 코드에 손대지
> 않는 격리 구조가 설계돼 있다.

## 5. 지도 탭

**상태**: 미착수 · **계획서 재작성 필요** · 상세: [`pending/map_plan.md`](pending/map_plan.md) (120줄)

### 왜

주소 데이터(`addr_split` 로 시도/시군구 분리됨)를 지도에 얹어 보는 화면. Leaflet + GeoJSON.

### 막는 것

- 요구가 확정되지 않았다.
- **계획서가 낡았다.** React 전환 이전의 vanilla-JS 구조(`web/js/map.js`)를 전제로 쓰여 있어
  6곳이 현재 코드와 맞지 않는다. 착수하려면 **먼저 다시 써야 한다.**

## 6. 로컬 GUI (Gradio/PyQt)

**상태**: 미착수 · **4번과 중복** · 상세: [`pending/gui_plan.md`](pending/gui_plan.md) (282줄)

### 왜

비개발자(정책·행정 담당자)가 xlsx 를 올리고 설정을 시각적으로 조정하는 데스크탑 GUI.
Gradio → CustomTkinter → PyQt6 단계적 계획.

### 막는 것

- **4번과 목적이 같다**(설치 없이 로컬에서 쓰기). 택일해야 한다.
- 계획서가 `web/` 정적 대시보드를 전제로 쓰였다 — 그 사이 React 어드민 마법사(Step 1~3)가 생겨
  **"비개발자용 시각적 설정"이라는 목적은 이미 상당 부분 달성됐다.** 남은 차이는 "설치 없이
  오프라인"뿐이고, 그건 4번이 더 잘 푼다.

> **권고**: 이 항목은 4번에 흡수하거나 폐기하는 쪽을 검토할 것.

## 기록 — 이 로드맵이 생긴 이유

테마 시스템을 끝낸 뒤 "하드코딩이 이제 없는가" 점검에서 **색은 분리됐지만 타이포·간격·그림자는
여전히 코드에 있다**는 것이 드러났다(1번). 그 작업을 나중에 이어갈 수 있도록 남기면서,
흩어져 있던 `pending/` 5건도 함께 우선순위·종속·중복 관계를 정리해 넣었다.

`pending/` 의 상세 스펙 문서는 그대로 둔다 — 로드맵에 전문을 붓는 대신 결정에 필요한 정보만
여기 두고 상세는 링크한다. 다만 **우선순위·상태·착수 여부는 여기가 단일 출처**다.

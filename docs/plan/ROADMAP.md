## 0. 대시보드 행 편집 + clean_xlsx 왕복

**상태**: **1~11단계 구현 완료(2026-07-17) · 실데이터 검증은 원본 PC 에서** ·
상세: [`pending/dashboard_edit_plan.md`](pending/dashboard_edit_plan.md)

### 왜

대시보드에서 값을 고치면 차트·KPI 와 `clean_xlsx` 가 함께 갱신되고, 반대로 엑셀에서 고친 것을
되돌려 올릴 수 있어야 한다. 지금은 정제 결과를 고치려면 원본을 고쳐 파이프라인을 다시 도는
길밖에 없다.

### 핵심 난점

`output/<name>_cleaned.xlsx` 는 원본이 아니라 **`storage/raw` + `config.yaml` 에서 매번
재생성되는 파생물**이다. 거기에 직접 쓰면 **다음 `/run` 이 편집을 조용히 지운다.**
그래서 편집을 `overrides.json` 오버레이로 분리해 파이프라인 최종 단계에 얹는 구조를 택했다 —
이 계획의 절반은 UI 가 아니라 이 문제를 푸는 데 있다.

### 설계의 축

**저장 · xlsx 재생성 · 배포를 세 시점으로 분리한다.** 저장은 `overrides.json` + `data.json` 만
갱신하고(<1초, 차트 즉시 반영), `cleaned.xlsx` 는 다운로드·발행 시점에 지연 생성하며,
git 커밋·푸시는 **「발행」 버튼 1회**로 모은다. 셋을 묶으면 셀 하나 고치는 데 수십 초가 걸리고
(전체 파이프라인 + 슬라이서 zip 재작성), 편집 1회마다 **Vercel 배포 1회 + 원격 충돌 기회 1회**가
생긴다. 뒤처짐 판정은 새로 만들지 않고 기존 `/freshness` · `is_stale` 을 확장해 쓴다.

`storage/` 클라우드 이전(3번)은 **이 항목과 무관하다** — `storage/` 는 gitignore 라 git 에
0바이트를 기여한다. 3번의 동기는 무상태 컨테이너의 파일 소실이고, 로컬 API 우선인 지금은
그 동기가 없다.

### 막는 것

**1~11단계 구현 완료(2026-07-17). 자동 테스트 전부 통과(백엔드 421 · 프런트 417).
남은 것은 실데이터 검증뿐이고, 그건 원본 PC 에서만 된다.**

작업 PC 에 `storage/projects/` 가 비어 있어(= [multi_pc §2.1](../guides/multi_pc_data_sync.md)
의 "보기 전용 PC") 화면에서 끝까지 돌려보지 못했다.
→ **[계획서 §12](pending/dashboard_edit_plan.md#12--원본-pc-인수인계--여기서부터-이어서-한다)에
확인 항목 13개가 체크리스트로 있다.** 특히:

- **기존 프로젝트는 `/run` 을 한 번 다시 돌려야** 편집이 열린다 (`__row_id` 가 없어서 — 의도된 안전장치).
- **발행은 아직 아무도 눌러본 적이 없다.** 가드는 진짜 git 저장소로 테스트했지만 실제 원격에
  푸시한 적은 없다.
- 저장 지연 **~2.2초**(sangga 15k행) — 목표 1초를 못 맞췄다. 써 보고 판단할 것.

> ⚠️ **발행(git 푸시)** 은 [`multi_pc_data_sync.md`](../guides/multi_pc_data_sync.md) §3
> 이 금지하는 동작("원본 없는 PC 에서 커밋 → 원래 PC 발행물을 덮어씀")에 닿아 있다.
> 가드 3종이 그걸 막는다(`app/git_sync.py`, 테스트 17개).

## 0-a. 필터 항목이 콤마로 조각나는 버그

**상태**: 미착수 · 바로 착수 가능 · 0번과 무관(그 작업 중 실측하다 발견)

### 무엇이

`exporter.py:304` 가 다중응답을 지원하려고 값을 콤마로 쪼개 집계한다. 그런데 **값 안에 콤마가
들어 있으면 조각난다** — 필터 드롭다운에 뜻 없는 파편이 뜬다.

```
원본 값 : "학계(대학, 대학원 등)"
드롭다운: "학계(대학"  /  "대학원 등)"     ← 별개 항목 2개
```

실측: `gpu_4` 의 5개 컬럼이 이 상태(`소속기관 유형`·`GPU 사용 현황`·`활용 계획`·
`필요 GPU 기종`·`2-5. GPU 지원필요`). 다른 프로젝트는 해당 없음.

### 왜 안 터졌나

프런트 `matchesPattern`(`aggregate.ts:125`)도 셀 값을 **똑같이 콤마로 쪼개** 비교해서
**필터 기능 자체는 동작한다.** 라벨만 깨져 보인다 — 그래서 지금까지 버그로 인식되지 않았다.

### 무엇을

다중응답 구분자를 콤마 고정이 아니라 **컬럼별 설정**으로 뺀다(`ChartItem.sep` 가 이미 차트에는
있다 — 집계·필터에도 같은 개념을 적용). 또는 `split_binary` 처럼 파생 컬럼으로 분리된 경우와
자유 텍스트를 구분한다. 백엔드 집계와 프런트 매칭이 **같은 규칙**을 쓰는지가 핵심이다.

## 1. 디자인 시스템 완성 — 타이포·간격·그림자

**상태**: 미착수 · 바로 착수 가능 · 상세 계획서 없음(이 문서가 유일)

### 왜

[테마 시스템](complete/theme_system_plan.md)으로 **색과 모서리(radius)** 는 토큰화됐지만, 디자인의
나머지 축은 여전히 코드에 박혀 있다. 지금의 "테마"는 정확히는 **컬러 테마**다.

```
text-[11px] × 35곳,  text-[13px] × 26곳,  text-[10px] × 24곳,  text-[12px] × 15곳 …  (100곳 이상)
```

**테마를 토스로 바꿔도 글자 크기·폰트·간격은 그대로다.** 원본 가이드는 이 정보를 갖고 있는데
쓰지 않고 있다:

| 가이드 절 | 빌드가 파싱? | 출력에 사용? |
|---|---|---|
| ③ 컬러 시스템 | ✅ | ✅ |
| ⑥ Border Radius | ✅ | ✅ |
| ⑤ 스페이싱 | ✅ | ❌ **버려짐** |
| ⑦ Shadow / Elevation | ✅ | ❌ **버려짐** |
| ⑩ Motion | ✅ | ❌ **버려짐** |
| ④ 타이포그래피 | ❌ 서술형이라 파싱 불가 | ❌ |

### 무엇을

1. **타이포 위계 정의** — `text-[11px]` 같은 절대값 대신 역할 이름을 쓴다.
   `text-caption`/`text-body`/`text-title` … Tailwind v4 의 `@theme` 에 `--text-*` 로 등록.
2. **가이드 ④ 절 구조화** — 현재 서술형("Display: 56px / 800 / 1.05 / -0.025em")이라 자동 파싱이
   안 된다. 파싱 가능한 형태로 바꾸거나, 활성 15종만 `overrides/` 로 손으로 채운다.
3. **⑤⑦⑩ 출력 연결** — 이미 파싱하고 있으므로 `@theme` 매핑만 추가하면 된다.
   그림자는 `shadow-[0_-2px_10px_rgba(0,0,0,0.05)]` 3건도 함께 정리.
4. **100곳 이상 치환** — 색상 치환(276건) 때와 같은 방식. 역할 매핑표를 먼저 정하고 일괄 치환 후
   스크린샷 비교.

### 유의

- **폰트 자체는 별개 문제다.** 가이드는 Pretendard·Toss Product Sans 등을 지정하지만 웹폰트를
  실제로 싣는 건 다른 작업이다(용량·라이선스). 1차에서는 크기·굵기·자간만 다룬다.
- 색상 치환 때 배운 것: **범주형 팔레트와 고정 배경 문맥은 토큰화하면 안 된다**
  ([theme README](../../frontend/src/theme/README.md) 참조). 타이포에도 같은 함정이 있을 수 있다
  (예: 터미널 로그의 `font-mono`).

## 2. 배포 — Railway 이전

**상태**: 검토 중 · 상세: [`pending/railway_migration_plan.md`](pending/railway_migration_plan.md) (537줄)

### 왜

지금 어드민 API(FastAPI)는 **로컬에서만** 돈다. 공개 대시보드는 Vercel 정적 배포라 잘 돌지만
(백엔드 없이 자립), 프로젝트 생성·정제 실행은 로컬 백엔드가 떠 있어야 한다.

### 막는 것

**"어드민을 원격에서 써야 하는가"가 확정되지 않았다.** 지금처럼 로컬에서만 정제하고 결과만
배포하는 방식으로 충분하다면 이 작업은 불필요하다.

### 유의

- 이전하면 **3번(클라우드 스토리지)이 따라온다** — Railway 는 무상태 컨테이너라 로컬 디스크
  `/storage` 가 재시작 때 날아간다.
- `backend/Dockerfile` 은 이미 pip 기반으로 정리돼 있어 컨테이너화 준비는 돼 있다.

## 기록 — 이 로드맵이 생긴 이유

테마 시스템을 끝낸 뒤 "하드코딩이 이제 없는가" 점검에서 **색은 분리됐지만 타이포·간격·그림자는
여전히 코드에 있다**는 것이 드러났다(1번). 그 작업을 나중에 이어갈 수 있도록 남기면서,
흩어져 있던 `pending/` 5건도 함께 우선순위·종속·중복 관계를 정리해 넣었다.

`pending/` 의 상세 스펙 문서는 그대로 둔다 — 로드맵에 전문을 붓는 대신 결정에 필요한 정보만
여기 두고 상세는 링크한다. 다만 **우선순위·상태·착수 여부는 여기가 단일 출처**다.

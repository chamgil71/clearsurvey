본 보고서는 설문 데이터 정제 시스템의 실무 신뢰성, 필터 사용성 및 엑셀 리포트 독립 구동 기능을 체계적으로 개선하기 위해 설계된 종합 로드맵이며, 논의된 모든 개선 요구사항에 대한 구현과 검증을 100% 완료한 상태입니다.

## 1. 작성일 연도 추출 정제 규칙 (`date_year`) — [구현 및 검증 완료]

### ① 문제 정의 및 필요성
* **현황**: 날짜 표준화 규칙(`norm_date`)은 `YYYY-MM-DD` 형태로 날짜를 보정하지만, 대시보드나 필터에서 **연도별(예: 2026년) 추이 분석**을 하려면 월/일 정보가 포함되어 있어 통계 그룹화가 어렵습니다.
* **해결**: 날짜 원본 데이터에서 4자리 연도 숫자(`YYYY`)만 정확히 추출하여 연도 기준 그룹핑 및 필터로 사용할 수 있는 `date_year` 정제 변환 규칙을 신설 및 UI 개방했습니다.

### ② 구현 설계 및 처리 로직
* 날짜 문자열(예: `2026-06-30`, `2026/05/11`, `2026년 04월`)에서 정규식 `(?:\D|^)(\d{4single})(?:\D|$)` 또는 Pandas DateTime 파서를 사용하여 4자리 연도 정보를 정수형(`2026`)으로 추출합니다.
* 프론트엔드 설정 에디터(`Step2_ConfigEditor.tsx`)에 정제 규칙 옵션으로 바인딩을 완료하여 사용자가 마우스 클릭으로 날짜 연도 컬럼을 정의할 수 있습니다.

## 2. 복수 선택 문항 다중 이진 플래그 열 분리 규칙 (`split_binary`) — [구현 및 검증 완료]

### ① 문제 정의 및 필요성
* **현황**: `"GPU 활용 계획"` 문항과 같이 한 셀에 `"AI모델, 데이터, 추론"` 등의 복수 항목이 콤마로 연결되어 입력된 경우, 기존 `to_binary` 규칙을 걸면 1개의 결과 열에 단순 `1`만 채워져 키워드별 상세 통계를 집계할 수 없습니다.
* **해결**: O열의 원래 텍스트 정보를 훼손하지 않으면서, `flag_keyword`에 지정된 키워드별로 대응하는 파생 이진 열(예: `GPU 활용 계획_AI모델`)을 결과물 시트에 동적으로 분리 확장해 주는 `split_binary` 규칙을 도입했습니다.

### ② 구현 설계 및 백엔드 파생 열 확장 매커니즘
* **설정 방식**: `config.yaml` 에서 특정 설문 문항에 `transform: split_binary`를 지정하고 `flag_keyword: "AI모델, 데이터, 추론"` 을 지정합니다.
* **동적 열 분리**:
  * 파이프라인 정제 엔진(`writer.py` 및 `pipeline.py`)이 결과 엑셀 시트에 원래의 `output_col` 외에, 각 키워드에 대응하는 파생 열들(`output_col_키워드`)을 동적으로 우측에 인서트합니다.
  * 각 행의 원본 텍스트에 해당 키워드가 포함되어 있다면 `1`, 없으면 `0`을 기입합니다.
* **대시보드 차트 연동**:
  * 동적으로 생성된 파생 열들은 `exporter.py`를 거쳐 `dashboard.json` 에 최종 열 메타데이터로 제공됩니다.
  * 사용자는 차트 빌더에서 `multibar` 차트 카드 설정 패널을 통해 개별 키워드 파생 열들을 클릭 한 번으로 추가하여 통계를 완벽히 도넛/막대 그래프로 시각화 집계할 수 있게 되었습니다.

## 3. aggregates 필터 드롭다운 항목 누락 결함 조치 계획 — [구현 및 검증 완료]

### ① 현상 분석 및 원인 규명
* **현황**: 대시보드 뷰어의 상단 필터바에서 `"소속기관"` 등 고유값이 많은 특정 드롭다운 필터를 클릭하면, 하위 선택 아이템 목록이 표시되지 않고 텅 비어 있던 현상.
* **원인**: 백엔드 데이터 익스포터(`exporter.py`)가 웹 대시보드 필터용 `aggregates` 데이터셋을 수집할 때, 고유값 갯수가 25개를 초과하는 열은 연산에서 아예 배제했기 때문입니다.
* **해결 조치**:
  * 컬럼의 `type`이 범주형(`category`)이거나 슬라이서에 등록된 필터 열(`include_in_slicer: true`)인 경우는 **고유값 개수와 무관하게 aggregates 범주 집계 데이터 목록을 강제로 빌드 및 보존**하도록 필터 통과 조건을 개정하여 버그를 완치하였습니다.

## 4. 오프라인 단독 실행형 HTML 보고서 내보내기 기획 — [구현 및 검증 완료]

### ① 필요성 및 유스케이스
* **필요성**: 웹 관리자 화면이 구동되지 않는 오프라인 내부망이나, 클라이언트가 백엔드 서버 없이 HTML 파일 하나만 열어 대시보드를 확인하고자 하는 실무 요구사항에 대응합니다.
* **요구사항**: 특정 프로젝트의 정제 완료된 모든 메타데이터, 차트 구성, 테이블 행 데이터를 단일 HTML 안에 주입하여 배포할 수 있어야 합니다.

### ② 시스템 아키텍처 및 구현 방식
* **API 엔드포인트 신설**: `GET /api/projects/{name}/export-html` 호출 시, 백엔드에서 정제된 JSON 데이터를 바탕으로 독립 실행형 자바스크립트가 인젝트된 HTML 보고서를 스트리밍 반환합니다.
* **CDN 라이브러리 연동**: TailwindCSS (스타일), Chart.js (동적 차트 렌더러), SheetJS (엑셀/CSV 파서 및 다운로더)를 탑재합니다.
* **클라이언트 로직 내장**:
  * `window.DASHBOARD_DATA` 변수에 전체 데이터셋을 바인딩합니다.
  * 사용자가 키워드를 입력하거나 슬라이서를 선택하면 브라우저 메모리상에서 실시간으로 데이터를 필터링하고 KPI 수치 재계산, 차트 리드로잉 및 테이블 페이지 갱신이 일어나도록 순수 바닐라 JS 필터링 루프를 내장하였습니다.
  * 필터링된 결과물 전체를 즉시 CSV 파일로 로컬 다운로드시키는 내장 스크립트 단추를 탑재하여 기능적 완성도를 보장하였습니다.

## 5. 정제 완료 시 실시간 대시보드 노출 자동화 — [구현 및 검증 완료]

### ① 원인 및 개선 방안
* **문제점**: 사용자가 프로젝트를 생성하거나 정제를 실행한 직후, 대시보드 목록 드롭다운에 신규 프로젝트가 실시간으로 보이지 않아 "웹 게시(Publish)" 수동 스위치를 매번 찾아 토글해야 했던 결함.
* **조치**: 파이프라인 가동 완료 스레드(`_run_pipeline_background`) 끝부분에 프로젝트 매니페스트(`projects.json`)의 `published: true` 웹 공유 승인 비트를 강제 갱신하도록 패치하여, 정제 성공 즉시 드롭다운에서 바로 확인하고 스위칭할 수 있도록 사용성을 대폭 끌어올렸습니다.

## 6. 대시보드 차트 데이터 정렬(소팅) 기준 제어 옵션 신설 — [구현 및 검증 완료]

### ① 필요성 및 유스케이스
* **현황**: 대시보드에 나타나는 차트 데이터들의 정렬 순서가 고정(단순 내림차순)이어서 가나다 순서로 정렬하거나 오름차순으로 역배치하는 등의 정렬 제어가 불가능했습니다.
* **해결**: 대시보드 차트 시각화 카드 설정에 `sort_by` 속성을 신설하고, 정렬 코어를 주입해 사용자가 원하는 기준으로 차트를 정렬할 수 있게 했습니다.

### ② 구현 세부내용
* `Step2_ConfigEditor.tsx` 의 차트 개별 카드 설정 영역에 `정렬: 값 내림차순 / 값 오름차순 / 이름 가나다 / 기본 순서` 콤보박스를 배치했습니다.
* `ChartCard.tsx` 및 오프라인 HTML 렌더러단에 한글 로케일 비교(`localeCompare("ko")`)를 지원하는 JavaScript 정렬 코드를 주입하여, 선택한 정렬 룰이 즉각 연동되도록 조치했습니다.

## 7. 다중 컬럼 합산(`group_sum`) 및 수치 데이터 캐스팅 방어 조치 — [구현 및 검증 완료]

### ① 필요성 및 유스케이스
* **현황**: 여러 열들의 수치 값을 합산하는 `group_sum` 정제 규칙을 UI에서 선택했을 때 정작 합산 대상 열 번호(`source_cols`)를 적어넣을 입력창이 화면에 나타나지 않아 설정 저장을 할 수 없었습니다. 또한 파생 수치 열들이 내보내기 시 문자열로 처리되는 연동 버그가 있었습니다.
* **해결**: UI 상에 `source_cols` 전용 텍스트 필드를 개방하고, 백엔드/프론트엔드 전체에 수치 형변환 방어 로직을 내장했습니다.

### ② 구현 세부내용
* `Step2_ConfigEditor.tsx` 추가 인수 테이블 셀에 `NEEDS_SOURCE_COLS` 분기를 추가하여 `group_sum` 선택 시 `source_cols (예: 12, 13, 14)` 인풋창이 활성화되게 핫픽스했습니다.
* `exporter.py` 의 `_clean` JSON 직렬화 함수 및 `aggregate.ts` 의 `aggNumericSum` 합산 함수에 numpy numeric 유형 검사 및 강제 형변환(`Number(val)`) 코드를 주입하여 문자열-숫자 혼종 상황에서도 100% 안전하게 누계 차트가 그려지도록 연동을 완치했습니다.

## 8. 2단계 저장 후 3단계 이동 시 정제 백그라운드 자동 실행(Auto-Run) — [구현 및 검증 완료]

### ① 필요성 및 유스케이스
* **현황**: 2단계 대시보드 레이아웃 설정창 하단에 `[디자인 저장 후 정제 테스트 및 실행 단계로 ➔]` 버튼이 있으나, 이 버튼을 누르고 3단계로 넘어간 뒤에도 사용자가 수동으로 `[실행(Run)]` 단추를 한 번 더 마우스 클릭해야만 실제로 파이프라인 정제가 가동되어 결과 JSON이 갱신되는 번거로운 이중 클릭 UX 구조였습니다.
* **해결**: 3단계로 전환되는 시점에 자동으로 정제 파이프라인 가동 및 SSE 실시간 로그 스트리밍 폴링이 백그라운드에서 자동 가동(Auto-Run)되게 설계했습니다.

### ② 구현 세부내용
* `admin.tsx` 의 위자드 2단계 ➔ 3단계 전환 핸들러(`onNext`) 내부에서, 3단계 뷰 전환(`setView("run")`) 직후 자동으로 `handleRunWithPolling()` 함수를 트리거하도록 비동기 호출을 연결했습니다.
* 이로써 사용자는 하단 버튼을 클릭하기만 하면 알아서 설정이 저장되고, 다음 실행 페이지에서 자동으로 정제가 구동되는 최상의 원클릭 가동 UX를 경험하게 됩니다.
